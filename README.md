# مدار — العامة والتعليم والإدارة

مستودع المشروع: https://github.com/smplsci/Prayer

## الروابط بعد تفعيل GitHub Pages

- العامة: `https://smplsci.github.io/Prayer/`
- التعليم: `https://smplsci.github.io/Prayer/education.html`
- المعلم: `https://smplsci.github.io/Prayer/teacher.html`
- المشرف: `https://smplsci.github.io/Prayer/admin.html`

العامة ترى المشهد والوقت الحالي، وتختار GPS بإذنها. يوجد إدخال يدوي للإحداثيات عند عدم توفر الموقع. منطقة الوقت وطريقة الحساب قابلة للضبط. المواقيت حسابية تقريبية وليست جدولًا رسميًا. لا ترسل المنصة إحداثيات الموقع إلى قاعدة بيانات التعلم.

## التشغيل والصيانة

`docs` شاشات النشر، و`src` مصادرها، و`backend` مخطط الخدمة المتصلة. افتح `docs/admin.html` محليًا لإعداد هوية الموقع والنشر. عند الحفظ تظهر رسالة تحقق قريبة من الزر؛ الحفظ المحلي يبقى في المتصفح ولا يغير ملفات GitHub. زر المعاينة يعرض التعديلات، وتصدير ZIP ينقلها لنسخة نشر جديدة.

شغّل `node src/prepare-platform.cjs` لإعادة تجميع الصفحات. تنفذ الفحوص من `src/tests`؛ اختبار الجهاز الحالي يستخدم مسار Playwright المرفق مع Codex ويمكن تعديل مساره عند تشغيله على جهاز آخر.

## النشر

ارفع `docs` والمصادر إلى المستودع. اختر **Settings → Pages → GitHub Actions**. يرفع `pages.yml` مجلد `docs` فقط. لا تُرفع ملفات نتائج الطلاب أو جلسات المتصفح أو كلمات المرور إلى المستودع. تُقفل أدوات الإدارة والمعلم على الموقع العام ما لم تُضبط خدمة الحسابات. معاينة الملفات المحلية ليست دخولًا محميًا.

## التخزين والحسابات

GitHub Pages يعرض ملفات ثابتة؛ ليس قاعدة بيانات. جهز مشروع Supabase ثم نفذ `backend/schema.sql` على مشروع جديد. ضع رابط المشروع والمفتاح العام فقط في `docs/cloud-config.js` وفي مصدره `src/cloud-config.js`. لا تضع `service_role` أو كلمة مرور فيهما.

أنشئ حسابك من Supabase Auth، ثم سجل معرّفه في جدول `profiles` بدور `admin` من SQL Editor. أضف المعلمين بدور `teacher`. لا تسمح السياسات للمعلم بمنح نفسه دور المشرف. دور المشرف يدير إعدادات الموقعين، والمعلم يحفظ مسودات مقرراته. النشر المركزي للإعدادات يتحقق من استجابة قاعدة البيانات للموقعين قبل إظهار النجاح.

الخدمة المتصلة **لم تُفعّل ولم تُختبر على قاعدة حقيقية دون مشروع Supabase**. جداول المسودات والتقارير مجهزة، لكن دخول المتعلم الضيف السحابي، وربط الصفوف والتكليفات، وتصحيح اختبارات رسمية على الخادم مراحل لاحقة. تظل تقارير الضيف محلية ويمكن استيرادها يدويًا. التقارير ذات التصحيح المحلي بيانات تعليمية غير موثقة للتقييم عالي المخاطر.

## Excel والنتائج

المتعلم ينزّل `XLSX` من النتائج. المعلم يستورد تقارير JSON ثم ينزّل تقريرًا مجمعًا أو Excel. يحتوي Excel معرف المتعلم والسؤال والمهارة والصحة والدرجة والمدة والثقة والتلميح وتاريخ المحاولة. الأرقام أرقام، والنصوص خلايا نصية وليست صيغًا، والصف الأول ثابت والورقة عربية من اليمين.

لا توجد بيانات شخصية مطلوبة للعامة. معرّف الضيف يتغير عند مسح بيانات المتصفح، وليس إثبات هوية. حفظ التقارير السحابي يتطلب حسابًا متصلًا؛ جمعها الآلي من ضيوف غير مسجلين لم يُفعّل.

## حدود التحقق

فحص محلي للأدوار، والحفظ وإعادة التحميل، وفشل التخزين، وGPS بإحداثيات محاكاة ورفض الإذن، والتأليف، وحدود الغروب، وExcel والجوال. توفر GPS الحقيقي يعتمد على الجهاز وإذن المتصفح. الصلاحيات المتصلة يجب اختبارها بحسابات مشروع حقيقي قبل تسليم النسخة الإنتاجية.
